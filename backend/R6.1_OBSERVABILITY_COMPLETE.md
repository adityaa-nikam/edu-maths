# Task R6.1 - Observability & Graceful Degradation

**Status:** ✅ COMPLETE

## Summary

Added comprehensive observability and degraded mode awareness to the EduMaths backend. The system now provides full visibility into Redis health, operation modes, and request tracing without changing any business logic.

---

## What Was Implemented

### 1. **Redis Health Tracker** (`src/utils/redisHealth.ts`)
- Tracks Redis connection state in real-time
- Maintains health status: `healthy` | `unhealthy` | `unknown`
- Signals system mode: `normal` | `degraded`
- Records consecutive failures and last error
- Provides uptime tracking
- Logs mode transitions automatically

### 2. **Request Correlation** (`src/middlewares/requestId.ts`)
- Generates unique UUID for each request
- Attaches `requestId` to req object
- Includes in response headers (`X-Request-ID`)
- Enables end-to-end request tracing
- Supports client-provided request IDs

### 3. **Structured Logger** (`src/utils/logger.ts`)
- Human-readable and machine-parseable logs
- Consistent format across all modules
- Automatic timestamp and context inclusion
- Log levels: `info`, `warn`, `error`, `debug`
- Filters sensitive data automatically
- Special methods for Redis and exam events

### 4. **Enhanced Redis Client** (`src/db/redis.ts`)
- Integrated health tracking
- Structured logging for all events
- Connection state monitoring
- Automatic degraded mode detection
- Exports `getRedisHealth()` function

### 5. **Health Endpoints** (`src/routes/health.ts`)
- `GET /api/health` - Overall system status
- `GET /api/health/redis` - Detailed Redis status
- Returns JSON with health metrics
- HTTP status codes reflect system state:
  - `200` - Healthy or degraded (non-critical)
  - `503` - Critical (database down)

### 6. **App Integration** (`src/app.ts`)
- Request ID middleware applied globally
- Health routes mounted at `/api/health`
- Backwards compatible with existing routes

## Health Endpoint Response Format

### `/api/health`
```json
{
  "status": "healthy" | "degraded" | "critical",
  "timestamp": "2026-01-21T10:30:00.000Z",
  "uptime": 3600000,
  "services": {
    "backend": { "status": "healthy" },
    "database": { "status": "healthy" },
    "redis": {
      "status": "healthy" | "unhealthy" | "unknown",
      "mode": "normal" | "degraded",
      "lastChecked": "2026-01-21T10:30:00.000Z",
      "consecutiveFailures": 0
    }
  }
}
```

### `/api/health/redis`
```json
{
  "status": "healthy",

  "lastStatusChange": "2026-01-21T10:00:00.000Z",
  "consecutiveFailures": 0,

}
```

## Logging Examples

### Normal Operation
```
ℹ️ [2026-01-21T10:30:00.000Z] Redis client connected | event="redis_connect"
ℹ️ [2026-01-21T10:30:00.000Z] System operating in normal mode | mode="normal"
```

### Degraded Mode
```
❌ [2026-01-21T10:30:00.000Z] Redis connection error | event="redis_error" error="ECONNREFUSED"
⚠️ [2026-01-21T10:30:00.000Z] System entering degraded mode: Connection closed | mode="degraded"
```

### Recovery
```
✅ [2026-01-21T10:35:00.000Z] Redis recovered - entering normal mode | event="redis_recovered" previousFailures=5 downtimeDuration=300000
```
